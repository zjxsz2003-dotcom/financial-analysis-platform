# 📊 企业经营分析预警系统

> 面向企业内部财务BP的业财融合智能分析平台 —— 秋招面试Demo项目

---

## 🎯 项目定位

这是一款**模拟企业内部FP&A工作流**的经营分析预警工具。系统以立讯精密（002475）为Demo案例，基于公开年报数据，演示了财务BP日常工作中最核心的五个场景：

| 模块 | 解决的问题 | 财务BP日常工作对应 |
|------|-----------|------------------|
| 📊 **业财融合看板** | 钱从哪来、花到哪去？ | 月度经营分析、业务板块复盘 |
| 🚨 **指标监控预警** | 哪里出问题了、多严重？ | KPI仪表盘监控、异常信号识别 |
| 💰 **预算偏差分析** | 实际vs计划差多少、为什么？ | 预算执行跟踪、偏差归因汇报 |
| 🎯 **战略目标追踪** | 离年度目标还有多远？ | 战略落地追踪、经营预测 |
| 📄 **自动化报告** | 一键生成老板要的报告 | 月度/季度/年度经营分析报告 |

**核心亮点：五模块穿透联动** — 从预警信号可一键追溯业务根因 → 预算偏差 → 战略影响，形成完整的分析闭环。

## 🚀 快速开始

### 环境要求
- Python 3.8+
- Windows / macOS / Linux

### 安装运行

```bash
# 1. 克隆或下载项目
cd AI财务分析网页

# 2. 创建虚拟环境（推荐）
python -m venv venv
venv\Scripts\activate  # Windows
# source venv/bin/activate  # macOS/Linux

# 3. 安装依赖
pip install -r requirements.txt

# 4. 启动应用
streamlit run app.py
```

浏览器自动打开 `http://localhost:8501`，点击"一键加载示例数据"即可开始体验。

### 激活AI分析（可选）

在侧边栏输入 DeepSeek API Key（[免费获取](https://platform.deepseek.com)），即可激活AI驱动的报告摘要生成。

> 不填API Key也能正常使用全部功能，系统会自动使用模板摘要。

## 📊 指标体系

### 五大维度 · 12项核心指标

| 维度 | 指标 | 预警逻辑 |
|------|------|---------|
| **盈利能力** | ROE、毛利率、净利率 | 低于行业均值1个标准差→🟡；1.5个标准差→🔴 |
| **偿债能力** | 流动比率、资产负债率 | 负债率>65%→🟡；>80%→🔴 |
| **营运能力** | 存货周转率、应收周转率 | 周转率连续恶化→🟡；低于警戒线→🔴 |
| **成长能力** | 收入增长率、净利增长率 | 增速<行业均值且为负→🔴 |
| **现金流质量** | 经营现金流/净利润、自由现金流 | 比率<0.7→🟡；<0→🔴 |

### 高新制造特色指标（业财看板）
- 研发费用率 + 资本化比例
- 前五大客户/第一大客户收入占比
- 各业务板块毛利率分化度
- 固定资产周转率 + 人均创收

## 💡 面试讲解词

### 30秒电梯演讲
> "我搭建了一套模拟企业内部FP&A工作流的企业经营分析预警系统。包含业财融合看板、五大维度指标监控、预算偏差分析和战略目标追踪，最后自动生成管理层经营分析报告。五个模块之间支持穿透分析——从预警信号可以一键追溯到业务根因。用立讯精密的公开年报数据做Demo，但系统架构完全按真实企业FP&A设计。"

### 常见追问应对

**Q: 为什么不用现成的BI工具（Power BI/Tableau）？**
> BI工具擅长可视化，但不内置会计专业知识——比如毛利率下降，BI只能展示趋势，我的系统会告诉你可能是哪个业务板块拖累的、和预算差多少、会影响哪个战略目标，这是财务BP的专业判断逻辑。

**Q: 公开数据和内部ERP数据有什么区别？**
> 公开年报数据颗粒度粗（只有年度、分部级别），真实企业有ERP实时数据可以做日/周监控、按SKU/客户/渠道维度分析。系统架构已预留这些接口——在面试中说明这点，反而体现你了解企业实际情况。

**Q: 这个系统实际工作中有用吗？**  
> 非常有用。金蝶、用友、Oracle EPM、Datarails这些主流FP&A工具的核心功能就是指标监控+预算管理+战略追踪+智能报告。我的Demo虽然用公开数据，但功能设计完全对标这些企业级工具。

**Q: 技术零基础怎么做到的？**
> Streamlit框架让我不需要写前端代码，把全部精力投入到会计专业逻辑和指标体系设计上。AI工具辅助了代码编写——这也正是财务数字化转型的核心能力：不是要成为程序员，而是能用技术工具解决财务问题。
